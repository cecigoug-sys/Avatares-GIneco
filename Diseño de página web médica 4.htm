5.4 Motor de respuesta recomendado

Para evitar invención de datos clínicos, el sistema debe usar una lógica de tres capas:

Capa 1. Clasificación de intención

Identifica si la pregunta se refiere a:

  • Motivo de consulta.

  • Dolor.

  • Tiempo de evolución.

  • Antecedentes.

  • Medicamentos.

  • Alergias.

  • Síntomas asociados.

  • Factores de riesgo.

  • Estado emocional.

  • Pregunta fuera del caso.

Capa 2. Búsqueda en el guion clínico

Busca la respuesta autorizada en la matriz del caso.

Capa 3. Respuesta segura

Si no existe información en el caso, el avatar debe responder:

  • “No sé.”

  • “No recuerdo.”

  • “No me lo han preguntado antes.”

  • “Eso no está claro para mí.”

  • “Prefiero que me explique a qué se refiere.”

Nunca debe inventar síntomas, diagnósticos, antecedentes ni resultados.

Prototipo mínimo viable para la práctica de entrevista clínica, comunicación médico-paciente y razonamiento clínico inicial en estudiantes de medicina.

2. Presentación del proyecto

El presente documento describe el diseño técnico inicial de una página web educativa orientada a la simulación clínica mediante pacientes-avatar.

El prototipo se plantea como una primera versión funcional, alojada en GitHub Pages, utilizando tecnologías web básicas:

  • HTML.

  • CSS.

  • JavaScript.

  • Archivos JSON para casos clínicos cerrados.

  • Voz sintética del navegador.

  • Rúbricas editables.

  • Respuestas controladas.

La finalidad principal es validar el modelo educativo antes de desarrollar una plataforma más compleja con base de datos, registro de usuarios, panel docente avanzado, reportes y posible integración con inteligencia artificial.

3. Justificación

La formación médica requiere espacios seguros para practicar habilidades clínicas antes del contacto directo con pacientes reales. La simulación clínica permite al estudiante ejercitar la entrevista médica, organizar el interrogatorio, identificar datos relevantes y desarrollar comunicación profesional.

El uso de pacientes simulados mediante avatares digitales ofrece una alternativa inicial para reforzar estas habilidades en un entorno controlado, repetible y supervisable. En esta primera etapa, el valor educativo no dependerá de la complejidad visual del avatar, sino de la calidad del caso clínico, la congruencia de las respuestas y la alineación con el programa educativo de la escuela de medicina.

Por ello, se propone iniciar con un prototipo mínimo viable en el que los casos sean cerrados, las respuestas estén previamente diseñadas y la evaluación se realice mediante rúbricas editables construidas a partir del programa educativo institucional.

4. Objetivo general

Desarrollar un prototipo mínimo viable de una página web educativa con pacientes simulados mediante avatares, que permita a estudiantes de medicina practicar entrevistas clínicas con casos cerrados, respuestas controladas, voz sintética del navegador y evaluación mediante rúbricas editables.

5. Objetivos específicos

  1. Diseñar una página web funcional alojada en GitHub Pages.

  2. Crear una estructura inicial para pacientes simulados con avatares simples.

  3. Incorporar casos clínicos cerrados en formato editable.

  4. Permitir que el estudiante realice preguntas clínicas por texto.

  5. Programar respuestas controladas del avatar con base en el guion del caso.

  6. Integrar voz sintética del navegador para reproducir las respuestas del avatar.

  7. Diseñar una rúbrica editable vinculada al desempeño del estudiante.

  8. Generar una pantalla final para impresión clínica, conducta inicial y retroalimentación.

  9. Validar el modelo educativo con docentes antes de migrar a una plataforma avanzada.

12. Motor de preguntas y respuestas

12.1 Principio general

El avatar no generará respuestas libres. Solo responderá con información previamente escrita en el caso.

12.2 Funcionamiento

El sistema analizará la pregunta del estudiante buscando palabras clave.

Ejemplo:

Pregunta del estudiantePalabras claveRespuesta activada
¿Desde cuándo empezó?desde cuándo, empezó, inicioinicio
¿Tiene dolor?dolor, dueledolor
¿Toma medicamentos?medicamento, tratamiento, tomamedicamentos
¿Es alérgico a algo?alergia, alérgicoalergias
¿Tiene antecedentes familiares?familia, madre, padre, hermanosantecedentesFamiliares
¿Qué síntomas tiene?síntomas, molestiassintomasAsociados

12.3 Respuesta cuando no hay información

Si la pregunta no corresponde al guion del caso, el avatar debe responder:

No sé o no recuerdo ese dato.

O bien:

No tengo información sobre eso.

Esto evita que el sistema invente datos clínicos.

13. Voz sintética del navegador

13.1 Función

El sistema podrá leer en voz alta la respuesta del avatar.

13.2 Código base

JavaScript
function hablar(texto) {
  if ("speechSynthesis" in window) {
    const mensaje = new SpeechSynthesisUtterance(texto);
    mensaje.lang = "es-MX";
    mensaje.rate = 0.95;
    mensaje.pitch = 1;
    window.speechSynthesis.cancel();
    window.speechSynthesis.speak(mensaje);
  } else {
    alert("La voz sintética no está disponible en este navegador.");
  }
}

13.3 Limitación

La disponibilidad, calidad y acento de la voz dependerán del navegador y del sistema operativo del usuario.

let ultimaRespuesta = "";

function ocultarTodo() {

function procesarPregunta() {
  const pregunta = document.getElementById("preguntaEstudiante").value.trim();

  if (pregunta === "") {
    alert("Escribe una pregunta clínica.");
    return;
  }

  agregarHistorial("Estudiante", pregunta);

  const respuesta = obtenerRespuesta(pregunta);
  ultimaRespuesta = respuesta;

  agregarHistorial("Paciente", respuesta);
  hablar(respuesta);

  document.getElementById("preguntaEstudiante").value = "";
}

function obtenerRespuesta(pregunta) {
  const texto = pregunta.toLowerCase();

  if (texto.includes("dolor") || texto.includes("duele")) {
    return casoActual.respuestas.dolor;
  }

  if (
    texto.includes("desde cuándo") ||
    texto.includes("cuando empezó") ||
    texto.includes("inicio") ||
    texto.includes("empezó")
  ) {
    return casoActual.respuestas.inicio;
  }

  if (
    texto.includes("síntoma") ||
    texto.includes("molestia") ||
    texto.includes("acompaña")
  ) {
    return casoActual.respuestas.sintomas;
  }

  if (
    texto.includes("antecedente") ||
    texto.includes("enfermedad") ||
    texto.includes("padece")
  ) {
    return casoActual.respuestas.antecedentes;
  }

  if (
    texto.includes("familia") ||
    texto.includes("madre") ||
    texto.includes("padre") ||
    texto.includes("hermano")
  ) {
    return casoActual.respuestas.familiares;
  }

  if (
    texto.includes("medicamento") ||
    texto.includes("tratamiento") ||
    texto.includes("toma algo")
  ) {
    return casoActual.respuestas.medicamentos;
  }

  if (
    texto.includes("alergia") ||
    texto.includes("alérgico") ||
    texto.includes("alergico")
  ) {
    return casoActual.respuestas.alergias;
  }

  if (
    texto.includes("fuma") ||
    texto.includes("alcohol") ||
    texto.includes("drogas") ||
    texto.includes("hábitos") ||
    texto.includes("habitos")
  ) {
    return casoActual.respuestas.habitos;
  }

  if (
    texto.includes("por qué viene") ||
    texto.includes("motivo") ||
    texto.includes("consulta")
  ) {
    return casoActual.respuestas.motivo;
  }

  return casoActual.respuestaNoDisponible;
}

20. Consideraciones éticas

20.1 Uso de pacientes ficticios

Todos los pacientes deberán ser ficticios. No deben utilizarse nombres, fotografías, voces, expedientes o datos que permitan identificar a personas reales.

La plataforma debe indicar claramente que se trata de un recurso de simulación clínica con fines educativos.

20.3 Supervisión docente

La evaluación obtenida en el prototipo no debe considerarse calificación definitiva sin revisión o autorización docente.

20.4 Limitación clínica

El sistema no debe utilizarse para orientar pacientes reales ni para emitir diagnósticos o recomendaciones médicas reales.

21. Aviso legal y educativo sugerido
